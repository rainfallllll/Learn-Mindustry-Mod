一、像素风演进：哪个版本开始不再是传统像素风
设置项「Pixelate Screen」（像素化屏幕）的历史，决定"默认画面是否像素风"：
时间版本事件默认画面
2017-05-14v33 前像素化渲染机制引入（低分辨率表面放大）像素
2017-11-20v33新增设置「Pixelate Screen」，默认开启（可选关闭）像素（可关）
2018-07~08v41~v48pixelate 设置被移除，渲染器重构（强制像素化，无开关）像素（强制）
2019-04-02v70pixelate 设置回归，默认改为关闭（提交 67a12eecad）——传统像素风结束，之后可手动开启像素化高清（默认）
结论：v70（2019-04-04）起默认不再像素风；想怀旧可随时在设置里重新开启 Pixelate。v7（v100+）之后画面与滤镜系统又整体升级过一次。

二·五、minGameVersion 各版本支持矩阵
mod.json 里写 "minGameVersion": "140.1"，游戏用它判断"我这个版本能不能跑这个模组"。检查逻辑与阈值随版本演进：
版本范围字段与检查实现过时/兼容阈值（模组声明值需 ≥）
v97–v100无字段，不检查—
v101–v104字段引入；isSupported() 自定义数字解析（build/revision 比较）无额外阈值
v105–v124自定义解析 + isOutdated() 判断105（<105 视为 v6 遗留模组 → 标记过时不加载）
v125–v135改用统一 Version.isAtLeast()（语义化 "140.1" 格式）105
v136–v146Version.isAtLeast()；阈值随 v136 同步提高（d92c9cfcf8）136（v8 时代，<136 视为 v7 遗留）
v147–v154.1Version.isAtLeast()；分模组类型设不同阈值（Vars.minModGameVersion / minJavaModGameVersion）脚本模组 136 / Java 模组 147
v154.2–v155同上（a552908d76 提高 Java 阈值）脚本 136 / Java 154
v156 起（当前 v159.7）Version.isAtLeast() + legacyCompatible 例外（16bbcb62e6）：仍兼容 v8 的 v7 模组可标记，旧 repo 双版本通用脚本 136 / Java 154（标记 legacyCompatible 可豁免）
要点：写模组时 minGameVersion 应 >= 当前目标版本的阈值；Java 模组在 v147 后被单独要求更高版本。当前（v159.7）数值定义在 Vars.java：minModGameVersion=136、minJavaModGameVersion=154。
